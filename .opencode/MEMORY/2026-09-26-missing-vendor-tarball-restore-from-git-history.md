# Missing workspace `file:` tarball breaks every root `bun install` while builds keep working

- 2026-09-26, opencode repo (workspace dependency resolution, project-agnostic)
- GOTCHA: a workspace `file:` dependency whose tarball is ABSENT from the tree makes EVERY root `bun install` fail (ENOENT extracting the tarball) while the already-populated `node_modules` keeps builds and tests green — the breakage only surfaces when a NEW dependency forces re-resolution. Observed: `packages/app/package.json:57` and `packages/session-ui/package.json:41` both require `file:vendor/opencode-ai-client-1.17.13-v2.tgz`, but the vendor dir actually held 1.17.14, so the required 1.17.13 blob was gone. A green build is therefore NOT evidence the dependency graph is intact.
- FIX: restore the exact blob from git history — `git log --all --oneline -- packages/app/vendor/` to find the commit that still held it, then `git show <commit>:<path> > <path>`. Do NOT try the bun cache or the npm registry: the bun cache had no entry and the npm `v2` prerelease 404s (it was never published). The file: dependency is only ever resolvable from the repo itself.
- ACCEPTANCE GATE: root `bun install` exits 0 and the lockfile saves (`bun.lock` updated, no ENOENT). Verify the tarball exists with a filesystem command (`ls`, `stat -f "%N %z bytes"`), never with glob/Read — vendored binaries are commonly gitignored, so a glob "No files found" is a visibility claim, not a missing-file verdict.
