# cua sb exec sudo: quote the whole command as ONE arg with a here-string (2026-10-03)
Running sudo inside a cua sandbox guest failed twice before working. cua sb exec does NOT forward host stdin, so `echo pw | sudo -S` arrives with an empty pipe, and a host-side <<< here-string is consumed by the LOCAL shell before the command ever ships. The pipe form also collapses through the exec quoting layers (sh -c joins args, splitting the command at the pipe).
Fix - quote the ENTIRE guest command as ONE argument so the guest shell applies the here-string itself (the cua macOS image own idiom, sudo_run: sudo -S -p EMPTY <<< PW, default password lume/lume): cua sb exec local:NAME -- (sudo -S -k systemsetup -settimezone Asia/Singapore <<< lume) with the parenthesized line single-quoted as one arg.
Gate: the guest-side command prints its success line (e.g. Set TimeZone: ...) and a follow-up `date` shows the changed result; the wrong-delivery forms print Password: then no password was provided.
