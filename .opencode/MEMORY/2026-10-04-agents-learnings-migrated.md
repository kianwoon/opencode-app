## Learnings (MANDATORY)
- After non-obvious rework, immediately write gotcha + correct command + acceptance gate into the narrowest auto-loaded layer (owning agent .md → project memory → global MEMORY, read-on-demand). NEVER the global/user AGENTS.md for domain or agent-specific lessons — it auto-injects into every session of every project. Future sessions load AGENTS.md automatically; do not rely on memory.
- Fork-scoped GitHub Actions tokens cannot mutate an upstream API target (403). Default cleanup scripts to `process.env.GITHUB_REPOSITORY`; verify with `GITHUB_TOKEN="$(gh auth token)" GITHUB_REPOSITORY=kianwoon/opencode-app bun script/github/close-prs.ts --dry-run --max-close 1 --print-limit 1`.
- Core config schema change ≠ app type change (hit twice: `classifier_model`, then `classifier.act`/`thresholds.retry_act`): adding a field to `packages/core/src/v1/config/*.ts` does NOT propagate to `packages/app` — regenerate the SDK: `bun ./script/build.ts` FROM `packages/sdk/js`. Never hand-edit generated files, and never locally widen an app type to mask the drift (it compiles but creates two sources of truth, silently). Acceptance gate: the field appears in `packages/sdk/js/src/v2/gen/types.gen.ts`, the widening is removed, `packages/app` `bun typecheck` exits 0.
- `context-gate` summarizer: never spawn an LLM helper session when a disk-cached summary exists (pinned-to-fallback window serves fallback text without a flight); cap background summarize flights to 1 per transform. Violation symptom: a `context-gate summary:` sidebar session per oversize section per LLM loop-step.
- Large-context subagent handoffs can flood the 4MB SSE cap and abort the task (reading `~/.local/share/opencode/log/opencode.log` WILL flood; repo-wide diffs on a dirty tree too). Scope handoffs to a few files, targeted offset/limit reads, no repo-wide diffs, capped report length, split multi-file work. Gate: the hand returns a bounded report instead of aborting.
- Correctness checks on large ACTIVE logs need the whole file, not a tail window — and the whole file is self-contaminated by your own diagnostics. Method for "has X ever happened?": (1) filtered whole-file count `grep PHRASE <log> | grep -v "evaluated permission" | wc -l` (raw `grep -c` counts are inflated by the permission-eval echo of your own grep); (2) report first/last match timestamps vs the event/restart time; (3) file-existence claims → re-stat path+mtime+line count at decision time and read the writer's actual sink — say "not yet observed at check time", never "never created"; (4) opencode.db LIKE queries match your OWN persisted command text — match the JSON field instead (`json_extract(data,'$.state.error') like '%PHRASE%'`) paired with a tool filter or time bound, and never a bare `>` in the SQL string (tripped the pre-2026-10-03 `*>*` deny; brain bash is blanket-allow since). Gate: assert "absent" only with a filtered whole-file count of 0 AND timestamps covering the period; otherwise "not observed in the window searched".
- Dual-source config footgun: one user-visible setting writable in two unconnected config paths silently no-ops (looks configured, never runs, NO error). Fix: resolve through ONE pure helper with explicit precedence at every read site; empty strings fall through. Instance: `resolveClassifierModel({override, brainModel, classifierModel})` — override > brain.classifier_model > classifier.model. Gate: unit tests assert override wins, brain wins over classifier, classifier-only works, all-absent returns `undefined`, empty strings fall through; the shadow observer skips entirely when the resolved model is absent.
- Agent model source of truth (brain.*_model keys REMOVED 2026-10-01): an agent's model lives SOLELY in `opencode.json` `agent.<name>.model` (Settings → Subagent Model write path). An `.md` frontmatter WINS any key it declares over `opencode.json`, so NEVER put `model:` in an `.md` whose model the Settings UI must edit — the UI write silently loses. Keep ONE source per key. Gate: `grep -c '^model:'` is 0 for each hand `.md`; `agent.<name>.model` carries the model; opencode.json parses (`python3 -c "import json;json.load(open('$HOME/.config/opencode/opencode.json'))"` exits 0).
- Pattern-scoped bash grants must deny redirection: `{"*": deny, "echo *": allow}` is NOT narrow — for a redirected command the pattern comes from the parent `redirected_statement` source text, so `echo x > /tmp/poc` matches the `echo *` allow = arbitrary file write. Append `"*>*": deny` LAST (`findLast`, last match wins; catches `>`/`>>`/`2>`/`&>`). It matches a `>` ANYWHERE in the source INCLUDING inside quoted echo text — keep echo protocol text free of literal `>`. Verify on the REAL tree-sitter parser (run through `ShellTool.execute` with a capturing `ask`, same harness as `test/tool/shell.test.ts`), never on assumed pattern strings; the deny relies on raw source text being embedded in patterns — re-verify if shell parsing changes. Gate: every redirect variant denied; clean echo allowed; `$(...)`/backticks/`;`/`&&`/`|` denied.
- Under narrow bash grants: never append `2>/dev/null`/`2>&1` (trips `*>*`); keep ONE allowlisted command per call (`;`/`&&`/`|` chains evaluate per segment — one un-allowlisted segment denies the whole call and innocent segments never run); use the `list` tool for directory listings. Exact syntax matters: `echo *` compiles to `^echo( .*)?$`, so `echo"text"` (no space) is denied with the generic message — check for a missing space before blaming the grant. Gate: `echo "text"` runs; `echo "x" 2>/dev/null` and space-less echo denied naming the rules.
- A fail-closed SECRET classifier is a fail-DENIED PERMISSION when quote-blind: `segments()` in `packages/opencode/src/plugin/execution-guard/classify.ts` must split only on separators OUTSIDE quotes (a quoted regex alternation torn into fragments failed closed to `package_install`, manufacturing a denial the agent cannot see coming); a single `&` (background) is NOT a separator, `&&` is; `policy.ts` also consumes `segments` — no regressions. Tell: a regex-bearing call denied naming `package_install` while a non-regex sibling succeeds = classifier bug, not a grant problem. 2nd shape (2026-10-04): `$(...)` command substitution with nested quotes tears the same way — `ASAR=…; echo "$(strings "$ASAR" | grep -c 'x')"` was denied naming `package_install`, while the plain `strings <path> | grep -c x` pipeline passed. Keep guard-sensitive calls to plain pipelines: no variable assignments, no `$(...)`, no decorative labels. Gate: quoted-alternation grep classifies `"other"`; `sh -c "npm install evil"` and `@#$%^&` classify `"package_install"`; `bun test test/plugin/execution-guard.test.ts test/tool/shell.test.ts` green from `packages/opencode`.
- Tool guidance prose is part of the schema contract: prose rendering a literal JSON token (`reuse:false`) teaches models to emit the STRING, which `Schema.Boolean` rejects as a hard SchemaError killing the call. Fix BOTH ends: widen to `Schema.Union([Schema.Boolean, Schema.Literals(["false"])])`, coerce at the single read site (never truthiness — `"false"` is truthy), reword prose to "pass reuse as the boolean false". Snapshot failing on a diff that only adds a union? Check the baseline first: `git log -1 -S '<failing literal>' -- <file>`. Gate: `{reuse:false}`, `{reuse:"false"}`, `{reuse:true}`, absent all decode; `grep -c 'reuse:false' packages/opencode/src/tool/task.ts` is 0; task-reuse + parameters tests + typecheck green.
- Agent-scoped `permission` flattens AFTER top-level `permission` into one ruleset and `findLast` makes it win ties — edit the agent block, not the top-level config, and RESTART after editing (external opencode.json edits are not hot-reloaded; only a UI write calls Config.invalidate()). The denial message names the winning rule — diagnose from the message first. Gate: under the scoped agent, a non-echo bash command is denied with the trio present and allowed after the agent block grants it — verified after a restart.
- Folding a permission layer must not wrap ACTION-ONLY keys: `todowrite`/`question`/`webfetch`/`websearch`/`doom_loop` are bare `"allow"|"ask"|"deny"` strings (`packages/core/src/v1/config/permission.ts`), not `Rule`. Rewriting them to `{"*": value}` stays semantically identical but fails ConfigInvalidError and the app won't boot — a semantic probe gate is NOT sufficient, gate on the real decode. Gate: every agent block has `typeof permission[k] === "string"` for those keys; config decodes.
- Agent-facing permission knowledge has ONE generated source of truth: the effective-permissions manifest in each session's system prompt (`fmtPermissions` from `Permission.merge(agent.permission, session.permission)` — the exact ruleset `Permission.ask` evaluates). Hand-written prose about grants WILL drift — prose is advisory, the manifest is authoritative. Gate: `bun test test/session/system-permissions.test.ts` green; every denial's matched rule appears in the session's manifest.
- `context-gate`'s system[0] round-trip is LOSSY — never re-emit a parsed cached prefix (`stripProvenance` + `joinSections` ≠ input bytes; `applyCaching` pins breakpoints on the first 2 system parts, so a byte change re-bills the prefix). The plugin must RETURN BEFORE ANY MUTATION when scoping and summarize are both off — and a guard placed AFTER the work it guards is inert; verify placement by re-reading the exact lines. Gate: zero new `"gate"` events in `~/.local/share/opencode/context-gate.jsonl` after restart; warm hit rate ≥90%; `bun test context-gate-roundtrip.test.ts` FROM `.opencode/plugin-lib`.
- A guard placed after the work it guards is inert, and a feature's escape hatch may be a SECOND variable: grep for the READER of the variable a feature writes and check for another variable holding the same object before declaring a write dead (JEV tool routing looked inert but escapes via `gatedHead`; it is ONE-SHOT-PER-SESSION — only the first turn's verdict shapes the frozen emitted head).
- External plugins in `.opencode/plugin-lib/` load through NODE native ESM, which requires explicit file extensions: an extensionless relative import throws and the plugin is SILENTLY dropped from boot (one log line). Both `bun build/test` and `tsc` resolve extensionless — passing them is NOT evidence. Probe the REAL loader: `node --experimental-strip-types --input-type=module -e "await import('<abs>')"` → exit 0. Scope: modules executed as SOURCE under Node (plugin-lib, externalized/lazy modules); Bun-bundled packages resolve at build time — establish the untouched-sibling baseline before probing one, and never rewrite repo-wide import style. Gate: node probe exit-0 on every edited plugin-lib module; post-restart no NEW "failed to load external plugin" lines (compare timestamps); functional boot check.
- Bun-only builtins (`bun:sqlite`) are externalized into the asar and kill Node/Electron boot (`Received protocol 'bun:'`) while verify-prod, asar markers and bun tests all pass — none exercise runtime resolvability. Fix: lazy dual-runtime loader, branch imports in-branch (`typeof Bun !== "undefined"` → `bun:sqlite`, else `node:sqlite`). Gate: node probe exit-0 pre-build; post-rebuild FUNCTIONAL boot (app opens, newest boot log greps 0 for the error string).
- Parallel sessions share one working tree — another session's commit can sweep your uncommitted work. Before a commit handoff check `git log --oneline -5` and `git show --stat HEAD`; stop only on an UNKNOWN hash/subject carrying your paths (same-file re-touch by this session's own known commits is expected). Gate: intended files in `git show --stat`, status clean, report names the hash.
- The `opencode-go` provider is runtime-resolved via auth.json + the fork's model registry — intentionally NOT in the config provider block; config audits must not flag it.
- V1 loop repetition guard: comparing only CONSECUTIVE turns is defeated by an ALTERNATING no-progress cycle. Progress = a tool-call signature the run has not already seen (run-scoped set), excluding `todowrite`/`todoread` (inputs churn cosmetically). Gate: `bun test test/session/prompt-stall.test.ts test/session/prompt.test.ts`, `bun typecheck`, from `packages/opencode`.
- Registry init + permission grant ≠ tool exposure: only the `builtin` array in `packages/opencode/src/tool/registry.ts` reaches models (`resolveTools` only FILTERS). Date the wiring: `git log -S "<tool>" -- packages/opencode/src/tool/registry.ts` — one commit = born-unexposed, two+ = added then removed. (Fixed 2026-10-02 for `jev_accept`/`jev_label`/`jev_rank`.) Gate: registry test asserts `registry.ids()` membership, Settings catalogs carry it, manifest grant and advertised tool set agree.
- Dead permission keys before a catch-all deny read as live grants but findLast denies them. The session's effective-permissions manifest is the truth: any key in config but absent from the manifest is DEAD — delete it or move it after the catch-all. Gate: `python3 -c "import json;json.load(open('$HOME/.config/opencode/opencode.json'))"` exits 0 and every permission key remaining in config appears in a fresh session's manifest. But keys can be UI-load-bearing: Settings-v2's denied()/howEntry resolved rules LITERALLY, so deleting evaluation-dead denies flipped 56 cua-driver MCP rows to "allowed" (2026-10-04) — make the renderer resolve findLast semantics before deleting apparently-dead keys.
- Config-is-injected contract: Settings → Agents checkboxes MUST equal a fresh session's callable toolset — verify by a FRESH-session flight (reused sessions replay their frozen head). Duplicate `owned_tools` keys in one agent block: json.load reads the LAST — count raw key occurrences. `jev.enabled: false` currently disables first-turn tool-routing persistence. Gate: fresh-session callable set sorts equal to the owned registry subset; no new `tool-routing applied` lines post-restart.

## Plugin-lib loading — the config array is the ONLY gate
- The discovery glob `{plugin,plugins}/*.{ts,js}` does NOT match `.opencode/plugin-lib/`; a file there loads ONLY via its absolute `file://` path in the config `plugin` array.
- INSTRUMENT — cite for any "is plugin X loaded?" claim, never a filename grep: `grep "external plugin discovery" ~/.local/share/opencode/log/opencode.log | tail -1` (failures log as `failed to load external plugin`).
- DANGER — never register a module with NO `default` export (the legacy fallback treats every exported function as a plugin instance and crashes). Registrable shapes only: `{id, server}` (v1) or `{id, effect|setup}` (v2). Probe before registering with the node import probe above.
- `opencode.json` is gitignored and NOT hot-reloaded — restart required.
- Gate: after restart, discovery lists the new entries AND no NEW "failed to load external plugin" lines (compare timestamps, filter `grep -v "evaluated permission"`).
