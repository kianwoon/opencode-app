## Build / Codegen
- Regenerate legacy JS SDK via `./packages/sdk/js/script/build.ts`.
- `bun run --cwd packages/sdk/js generate` FAILS — `packages/sdk/js/package.json` has no `generate` script (`error: Script not found "generate"`). Run `bun ./script/build.ts` FROM `packages/sdk/js` instead (invokes `@hey-api/openapi-ts`, writes `src/v2/gen`). Note `packages/client`'s `generate` script is a DIFFERENT codegen (`src/generated`/`src/generated-effect`); do not confuse the two. Acceptance gate: a new core-schema field (e.g. `classifier_model`) appears in `packages/sdk/js/src/v2/gen/types.gen.ts` AND any app-side type widening added only to work around the missing field is removed.
- After Protocol/Server `HttpApi` change: `bun run generate` from `packages/client`; never edit `src/generated` / `src/generated-effect`.

## Style
- One function unless composable/reusable; no preemptive single-use helpers; inline single-use values.
- No `try/catch` where possible; no `any`; use Bun APIs (`Bun.file()`); rely on inference.
- Prefer `map/filter/flatMap` + type guards over loops.
- `src/config`: self-export pattern (`export * as ConfigAgent from "./agent"`).
- Effect generators: bind services to named vars; no `yield* (yield* Foo.Service).bar()`.
- No unnecessary destructuring (use `obj.a`); no import aliases; no star imports.
- Namespace by name: `import { Project } ...`, use `Project.ID`.
- Dynamic imports for heavy/path-specific modules, destructured at top of narrowest scope; no `.then` chains; keep branch imports in-branch.
- `const` over `let`; ternaries/early returns; no `else`.
- Complex logic: main fn = happy path, helpers below; only extract real concepts.
- Helpers don't return `Effect` unless effectful; keep sync parsing/validation sync.
- Prefer `Schema.UnknownFromJsonString` / `Schema.decodeUnknownOption` over `JSON.parse`+`Effect.try`.
- Comment only non-obvious constraints.
- Drizzle: `snake_case` fields so columns need no string rename.

## Testing
- No mocks; no `globalThis.*` unless only option; test real impl, don't duplicate logic.
- Never run tests from repo root; run from package dirs (e.g. `packages/opencode`).

## Typecheck
- `bun typecheck` from package dir, never `tsc` directly.

## V2 Session Core (`packages/core` + `packages/opencode`)
- `SessionV2.prompt()` = admit 1 durable `session_input` row + advisory `SessionExecution.wake()` unless `resume:false` (admit-only); runner promotes at safe boundaries.
- Session ID reuse adopts session; prompt ID reuse = exact retry only if session+prompt+delivery match.
- `SessionExecution` process-global, Session-ID based; placement via `SessionStore`+`LocationServiceMap` only at drain start; interruption = active local chain, idle = no-op.
- `SessionRunner`/models/tools/permissions/filesystem are Location-scoped; omitted workspace = implicit-local.
- One `llm.stream()` per provider turn; reload projected history; no legacy `SessionPrompt.loop`.
- Drains process-local; `SessionRunCoordinator` joins same-session resumes, coalesces wakes, concurrent different sessions; no durable drain identity; post-crash retry needs explicit design.
- Delivery: `steer` (default, promote at next safe boundary) vs `queue` (pending until idle, promote one at a time); any promotion resets agent turn allowance (batch steers = once).
- EventV2 replay owner ≠ execution owner; System Context algebra/registry in `packages/core/src/system-context`; History selection + Epoch persistence Session-owned.

## Learnings (MANDATORY)
- After non-obvious rework-causing issues, immediately write concise gotcha + correct command + acceptance gate into relevant package `AGENTS.md` (or root if cross-cutting); repeat mistake = must document.
- Core config schema change ≠ app type change (occurred TWICE: `classifier_model`, then `classifier.act`/`thresholds.retry_act`): adding a field to `packages/core/src/v1/config/*.ts` does NOT propagate to `packages/app` — the generated SDK type (`packages/sdk/js/src/v2/gen/types.gen.ts`) is a separate artifact and must be regenerated. Until it is, devs "fix" it by locally widening a type (e.g. `createMemo<{ enabled?: boolean; act?: boolean }>()`), which SILENTLY MASKS the drift: it compiles, but the config type now has two sources of truth. Fix: run `bun ./script/build.ts` FROM `packages/sdk/js` (the `generate` script does not exist there; `packages/client`'s is a DIFFERENT codegen) — do NOT hand-edit generated files if the @hey-api post-codegen patch throws. Acceptance gate: field appears inside the relevant config block in `types.gen.ts` AND the app-side widening is removed, with `packages/app` `bun typecheck` still exiting 0.
- Future sessions load `AGENTS.md` automatically; do not rely on memory.
- `context-gate` summarizer must never spawn an LLM helper session when a disk-cached summary exists (pinned-to-fallback window serves fallback text without a flight); cap background summarize flights to 1 per transform. Symptom of violation: a `context-gate summary:` sidebar session per oversize section per LLM loop-step.
- Large-context subagent handoffs can flood the 4MB SSE response cap and abort the task (`SSE stream exceeded 4194304 bytes; the response flooded and was aborted`). Causes seen: a hand told to read a huge file (`~/.local/share/opencode/log/opencode.log` is ~6.7MB — reading it WILL flood); a hand told to read AGENTS.md files that are already auto-injected; repo-wide `git status`/`git diff --stat` on a dirty tree (67 files). Scope handoffs to a few files, demand targeted offset/limit reads, forbid repo-wide diffs, cap the report length, split multi-file work into separate handoffs. Acceptance gate: the hand completes and returns a bounded report instead of aborting.
- Bounded-tail greps on a large ACTIVE log produce FALSE NEGATIVES for rare events (cost: a wrong "the feature never fired / PROVEN-ABSENT" claim; it was firing the whole time — 44 events). `opencode.log` grows to 10+MB in one session, so `tail -c 400000 opencode.log | grep "classifier.decision"` searches only the last ~400KB; one telemetry line per turn scrolls out fast, and a check run before the newest writes shows nothing even with a correct window. The anti-flood constraint above is real, but it must not silently degrade a *correctness* question. Correct method for "has X ever happened?": (1) whole-file COUNT, context-safe because it prints one integer — `grep -c "PHRASE" <logfile>`; (2) if nonzero, a bounded sample — `grep "PHRASE" <logfile> | grep -v "evaluated permission" | tail -8`; (3) always report FIRST/LAST matching timestamps and compare against the event/restart time; (4) noise trap — `message=evaluated permission=... pattern="...PHRASE..."` lines are the agent's OWN grep being permission-evaluated, not real events, so always filter `grep -v "evaluated permission"`. Acceptance gate: before asserting an event is ABSENT you need (a) a whole-file `grep -c` of 0, not a tail-window 0, AND (b) confirmation the file's mtime/timestamps cover the period in question; otherwise say "not observed in the window searched", never "proven absent".
- Dual-source config footgun (classifier model): one user-visible setting was writable in two unconnected config paths — Settings → Orchestration "Classifier model" writes `brain.classifier_model` (`packages/app/src/components/settings-v2/orchestration.tsx:151`, reusing the generic brain model-row `commit` → `updateConfig({ brain: {...} })`) while the backend shadow hook read top-level `classifier.model` (`packages/opencode/src/session/processor.ts:810`, `packages/opencode/src/classifier/service.ts:111`). Symptom: the toggle opened the gate but the model resolved to `undefined`, so the real transport silently degraded to the deterministic fallback — feature looked configured, never ran, NO error surfaced (the silent no-op is the dangerous part). Fix: resolve through ONE pure helper with explicit precedence — `resolveClassifierModel({ override, brainModel, classifierModel })` → first non-null/non-empty wins, order `override > brain.classifier_model > classifier.model` — used at every read site so precedence lives in exactly one place; empty strings fall through (absent, not a value). Keep `brain.classifier_model` working: it also sets the `classifier` AGENT definition's model (`packages/opencode/src/config/brain.ts:84`). Acceptance gate: a unit test asserting override wins, brain wins over classifier, classifier-only works, all-absent → `undefined`, empty strings fall through — plus the shadow observer skipping entirely when the resolved model is absent.
- Pattern-scoped bash grants must deny redirection (privilege escalation): a "narrow" grant like `bash: {"*": deny, "echo *": allow}` is NOT narrow. `packages/opencode/src/tool/shell.ts` derives permission patterns from **tree-sitter** parsing — nested `$(...)`/backticks and `;`/`&&`/`|` chains become SEPARATE patterns and are correctly blocked — but **output redirection is not covered**: for a redirected command the pattern comes from the parent `redirected_statement` source text, so `echo x > /tmp/poc` yields ONE pattern matching the `echo *` ALLOW = arbitrary file write (`>> ~/.zshrc`, `~/.ssh/authorized_keys`). `execution-guard` only denies `pipe_to_shell`/`remote_dependency`, not redirection. Fix: append a redirection deny LAST (order matters — `packages/opencode/src/permission/index.ts` uses `findLast`, so the LAST matching rule wins): `bash: {"*": deny, "echo *": allow, "*>*": deny}` (`*>*` catches `>`, `>>`, `2>`, `&>`, spaced or not). Verify on the REAL parser, NOT on pattern strings you assume it emits (first attempt here "passed" 12/12 against assumed strings): run the command through `ShellTool.execute()` with a capturing `ask` (same harness as `test/tool/shell.test.ts`), collect the REAL derived patterns, then evaluate with `Wildcard.match` + last-match-wins. Acceptance gate: every redirect variant (`>`, `>>`, `2>`, no-space `>`, `&>`) DENIED, `echo "🚀 text"` ALLOWED, `$(...)`/backticks/`;`/`&&`/`|` DENIED. Caveat: the deny works only because the parser embeds raw source text into the pattern — a future change to that derivation (quoting/normalization in `source()`) silently reopens the hole; re-verify if shell parsing changes.
- Narrow bash grants also require exact command syntax — a missing SPACE is a denial (the message does NOT say so): `echo *` compiles to `^echo( .*)?$`, so `echo "text"` is ALLOWED but `echo"text"` (no space) is DENIED with the generic "the user has specified a rule which prevents you from using this specific tool call" — indistinguishable from a real security block, so the agent wrongly concludes the grant is broken. The bash tool takes one `command` string: hand it the whole quoted command (`command: echo "🚀 text"`), never a malformed/uncollapsed payload that arrives as `echo"🚀 text"`. Diagnosis: if a narrow `echo *` grant denies a legitimate-looking echo, check FIRST for a literal space after `echo` in the raw text before blaming the grant or a security rule. Acceptance gate (on the REAL tool/parser, not the glob in the abstract): `echo "🚀 text"` runs and the redirection form is denied, while space-less `echo"x"` is denied.
- `context-gate`'s system[0] round-trip is LOSSY — never re-emit a parsed cached prefix: the plugin parsed `system[0]` and re-serialized it every turn, but `stripProvenance` (`.opencode/plugin-lib/context-gate.ts:597`) deletes a trailing `[Summarized from ~N words — original: ...]` marker and `joinSections` (`:224`) rebuilds each section as `` `Instructions from: ${path}\n${text.replace(/\n+$/,"")}` `` joined by `"\n"` with a forced single-`"\n"` prologue separator, so input bytes ≠ output bytes. Because `applyCaching` (`packages/opencode/src/provider/transform.ts:366`) pins cache breakpoints on the first 2 system parts + the latest user message, a byte change there re-bills the whole prefix. Observed symptom: warm turns dropping from ~62k `cache_read` to ~12k with ~54k fresh `input`. Fix: the plugin must RETURN BEFORE ANY MUTATION when both `scopingEnabled` and `summarizeEnabled` are false — guard now at `.opencode/plugin-lib/context-gate.ts:1020`; note `sections.splice` (`:1059`) and `applyGate(prologue, sections, ...)` (`:1063`) run BELOW it and are mutations too. Acceptance gate: (1) zero new `"gate"` events in `~/.local/share/opencode/context-gate.jsonl` after restart; (2) warm-turn hit rate from `~/.local/share/opencode/opencode.db` (`cache_read/(cache_read+cache_write+input)`) ≥90%; (3) the regression test `.opencode/plugin-lib/context-gate-roundtrip.test.ts` passes (run `bun test context-gate-roundtrip.test.ts` FROM `.opencode/plugin-lib`, never repo root).
- A guard placed AFTER the work it guards is inert — verify placement by re-reading the exact lines, never by trusting a diff summary: the first fix put the context-gate early return below `sections.splice` and `applyGate`, so it did not prevent the lossy rewrite, only skipped the memo/log tail. Same trap, same codebase: `packages/opencode/src/session/prompt.ts:2307` assigns the JEV verdict to `turnTools`, but `:2537` emits `tools: headTools` (session-frozen via `freezeHead`, `:2489`), and nothing downstream reads `turnTools` to build the request — so the whole JEV tool-routing feature is INERT while `jev.tool-routing applied {removed: N}` (`:2308`) still logs savings that never occurred. Acceptance gate: before claiming a feature saves anything, grep for the READER of the variable it writes, not just the write site — a write with no reader that feeds the request path is a no-op with telemetry.
- External plugins in `.opencode/plugin-lib/` are resolved by opencode's external-plugin loader through **Node** native ESM (stack: `Plugin.load` → `node:internal/modules/esm/loader`), NOT Bun. Node ESM requires EXPLICIT file extensions on relative specifiers: an extensionless import throws `Cannot find module '.../compaction-triage' imported from .../context-gate.ts at finalizeResolution (node:internal/modules/esm/resolve:275:11)` and the plugin is SILENTLY dropped from boot — no crash, no user-visible error, only one `message="failed to load external plugin"` line in `~/.local/share/opencode/log/opencode.log`. Three such specifiers (fixed 2026-09-22): `.opencode/plugin-lib/context-gate.ts:4` `"./compaction-triage"`, `.opencode/plugin-lib/task-effort-router.ts:18` `"../../packages/opencode/src/session/arbitrate"`, `.opencode/plugin-lib/compaction-triage.ts:16` `"./jev-effort"` (latent — would have failed the next restart) — all now import the `.ts` path. Blast radius: JEV tool routing, guardrail, effort routing and compaction triage were all dead from boot. The trap: BOTH standard checks PASS on an extensionless import — `bun build --no-bundle` and `bun test` resolve it (Bun is extension-tolerant), and `tsc`/`bun typecheck` also accept it — so neither the build nor the test is evidence for this class of bug. Correct check is the REAL loader: `node --experimental-strip-types --input-type=module -e "await import('<abs>/.opencode/plugin-lib/<name>.ts')"` (Node v24.6.0, same `finalizeResolution` that fails in production) → exit 0. Acceptance gate: the node probe exits 0 for every edited/added `plugin-lib/*.ts`, AND after a restart `grep -c "failed to load external plugin" ~/.local/share/opencode/log/opencode.log` shows no NEW lines (historical lines at ~36767 from 2026-09-21 remain — compare timestamps, not the raw count).
- Verify against the REAL runtime loader, not a bundler: when a file is executed by a different runtime than the one you test with, the passing test is not evidence about production. `bun build --no-bundle` / `bun test` resolving a specifier says NOTHING about Node ESM resolution, and a bundler's tolerance is exactly what hides the failure. Before claiming a plugin/hook change is verified: (1) grep the HOST APP for the loader that executes the file (here `Plugin.load` in `packages/opencode/src/plugin` → Node ESM `import()`), (2) exercise THAT loader with a minimal probe on the real entry path, (3) read the host's own error/log sink for the failure line rather than assuming a silent success. Acceptance gate: name the production loader in the report and paste the exit-0 probe output from it — a build/test exit code alone does not satisfy this.
