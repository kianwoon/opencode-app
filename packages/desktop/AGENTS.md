# Desktop package notes

## Building a production desktop app (`dist/mac-arm64/OpenCode.app`)

1. Confirm the user means the desktop app, not the CLI binary — the app never loads `~/.opencode/bin/opencode`; it runs its own server baked into `Resources/app.asar`. Check `ps aux | grep -i opencode` first (2026-08-31: rebuilding the CLI did not update the app; hours lost).
2. `OPENCODE_CHANNEL=prod bun run build` — bakes the channel into the server bundle in `out/`. `package:mac` does NOT rebuild; it packages whatever is already in `out/`, so skipping this step silently bundles a stale build.
3. `OPENCODE_CHANNEL=prod bun run package:mac` — produces `.app`/`.dmg`/`.zip`.
4. Acceptance gate: `verify-prod.ts` must print `✅ Verified <channel> build: ... embeds channel "<channel>" and uses <db>`. Never skip — dev and prod builds are visually identical; only this output proves which DB the app connects to (prod → `opencode.db`, else `opencode-<channel>.db`).

## Learnings

**Electron helper rename breaks child spawns (2026-09-15).** Symptom: packaged `OpenCode.app` aborts every child with `[FATAL:electron/shell/app/electron_main_delegate_mac.mm:66] Unable to find helper app` (helper procs exit 5 / SIGTRAP, `~/Library/Logs/DiagnosticReports/OpenCode Helper-*.ips`), so windows never render. Root cause: `GetHelperAppPath` probes `Frameworks/Electron Helper*.app/Contents/MacOS/Electron Helper*` (ELECTRON_PRODUCT_NAME) **first**, then the `<main CFBundleName> Helper*` fallback; electron-builder renames bundles/executables to `OpenCode Helper*` but leaves the inner `CFBundleName` as `Electron Helper*`, so the primary probe misses. Fix: `renameMacHelpers` `afterPack` hook in `electron-builder.config.ts` renames bundle + executable + `CFBundleExecutable` back to `Electron Helper*` (runs before signing, so signatures stay consistent). Gate: `ls Contents/Frameworks` shows `Electron Helper*.app` with matching `Contents/MacOS/Electron Helper*`, and launching with `OPENCODE_TEST_ONBOARDING=1` spawns gpu/renderer/utility children with zero `Unable to find helper` FATALs. Note: `--user-data-dir` is ignored (userData is hardcoded to `appData/<appId>`), so isolated launch tests need `OPENCODE_TEST_ONBOARDING=1`.

**CLI rebuild presented as a prod app update (2026-08-31).** Symptom: `~/.opencode/bin/opencode` was rebuilt and called "prod updated", but the user runs `packages/desktop/dist/mac-arm64/OpenCode.app`; the running `Resources/app.asar` had zero broker strings and `out/` was 11h stale. Root cause: this AGENTS.md was never read and no `ps aux | grep -i opencode` was run before choosing a build target, so the wrong artifact was built and the done-claim was false. Fix: run `ps aux | grep -i opencode` FIRST to see what is actually running; then `OPENCODE_CHANNEL=prod bun run build` (from `packages/desktop/`) before `OPENCODE_CHANNEL=prod bun run package:mac`; confirm with `verify-prod.ts` using `APP_DIR` plus `strings .../app.asar | grep` for the broker markers. Gate: `verify-prod` prints `✅ prod` against `opencode.db` AND `strings app.asar` shows `secret://project`.

**Dev-channel mac build unsigned despite declared entitlements (2026-09).** Symptom: Helper (GPU/network utility) children die at launch with byte-identical `EXC_BREAKPOINT`/`SIGTRAP` (`BRK #0`, <1s uptime), ~48×/day; main relaunches endlessly (813 "app starting" vs ~83 "server ready" in 3 days); main log shows nothing. Root cause: with `identity` unset and no valid keychain identity (0 valid; one untrusted `jarvis_voice-dev`), electron-builder silently skips signing — every Mach-O is linker-adhoc (`flags=0x20002`) with no `_CodeSignature/CodeResources`, no embedded entitlements, no hardened runtime, even though `electron-builder.config.ts` declares them. Diagnosis trick: `codesign --verify --deep` → `code has no resources but signature indicates they must be present` is the smoking gun; symbol-less `.ips` frames in `ElectronMain` are NOT enough. Fix (no Developer ID): after `package:mac`, reseal ad-hoc with entitlements: `codesign --force --deep --sign - --entitlements resources/entitlements.plist dist/mac-arm64/OpenCode.app`. Caveat: resealing AFTER packaging leaves `.dmg`/`.zip` unsigned — repackage/reseal extracted apps for distribution. Gate: `codesign --verify --deep dist/mac-arm64/OpenCode.app` exits 0, `codesign -d --entitlements - .../Contents/MacOS/OpenCode` shows all 6 entitlement keys declared in `resources/entitlements.plist` (5 `com.apple.security.cs.*` + 1 `com.apple.security.device.audio-input`; gate on PARITY with the plist, not a hardcoded cs-count — 2026-09-23: an "expect 6 cs" gate false-STOPped a green build because the plist actually declares 5 cs keys), all 4 `Electron Helper*.app` contain `_CodeSignature/CodeResources`, `APP_DIR=dist/mac-arm64/OpenCode.app OPENCODE_CHANNEL=prod bun run scripts/verify-prod.ts` prints `✅ Verified prod build`, and relaunch yields zero new `Electron Helper-*.ips` in DiagnosticReports.

**SQLite VACUUM and session deletion (2026-09-24).** Deleting a session can overlap SQLite’s writer transaction; the old external `sqlite3 VACUUM;` had no busy timeout or child deadline and could fail or hang the desktop. Fix: `packages/desktop/src/main/database-vacuum.ts` runs the real `sqlite3` command `PRAGMA busy_timeout = 5000; VACUUM;` with a 30-second `SIGKILL` deadline, delegated from `ipc.ts`. Acceptance gate: from `packages/desktop`, `bun test src/main/database-vacuum.test.ts` passes (the real Node `node:sqlite` harness is used because Bun 1.3.14 cannot load `node:sqlite`) and `bun typecheck` exits 0; production packaging additionally requires the existing prod build/verify sequence.
- **verify-prod does NOT check codesign — an UNSEALED artifact passes every gate (2026-09-25).** Symptom: 8 `Electron Helper-*.ips` child deaths in one day plus one abrupt whole-app termination, while `verify-prod.ts`, asar marker greps, and bun tests were ALL green — none of them inspect the signature. Root cause: `package:mac` with no valid keychain identity silently skips real signing, leaving the bundle `flags=0x20002(adhoc,linker-signed)` with NO `_CodeSignature/CodeResources` in the helper sub-bundles; `codesign --verify --deep` then exits 1 with `code has no resources but signature indicates they must be present`. Gate the SEAL, not the remedy (clarified 2026-09-26: the previous "ALWAYS reseal" wording caused the wrong call twice — once skipping the remedy, once nearly downgrading a valid signature). The ACCEPTANCE GATE is the observable state: `codesign --verify --deep dist/mac-arm64/OpenCode.app` exits 0 AND every `Electron Helper*.app` bundle under `Contents/Frameworks` contains `Contents/_CodeSignature/CodeResources` (`ls dist/mac-arm64/OpenCode.app/Contents/Frameworks/Electron\ Helper*.app/Contents/_CodeSignature/CodeResources` prints one line per helper; a missing one is the failure). When `package:mac` reports `type=distribution identityName=<real>` (observed `GlanceDev`), that gate is ALREADY satisfied — do NOT run the ad-hoc force-reseal, because `codesign --force --deep --sign -` DOWNGRADES a valid distribution signature to ad-hoc. The reseal remedy applies ONLY when the gate FAILS: signing produced no usable identity (electron-builder silently skips signing, leaving `flags=0x20002(adhoc,linker-signed)`) or any helper bundle is unsealed. In that case run `codesign --force --deep --sign - --entitlements resources/entitlements.plist dist/mac-arm64/OpenCode.app`, then `codesign --verify --deep dist/mac-arm64/OpenCode.app`, then RE-RUN `APP_DIR=dist/mac-arm64/OpenCode.app OPENCODE_CHANNEL=prod bun run scripts/verify-prod.ts` to prove the seal did not break the bundle.

**Seal-gate find pattern must include Contents/ (2026-09-25).** Helper CodeResources lives at `<Helper>.app/Contents/_CodeSignature/CodeResources`; a find -path pattern omitting the `Contents/` segment (`"*Helper*.app/_CodeSignature/CodeResources"`) returns 0 forever and false-FAILs a correctly sealed bundle (cost: 2 wasted gate rounds on a green artifact). Correct gate: `find dist/mac-arm64/OpenCode.app/Contents/Frameworks -maxdepth 4 -path "*Helper*.app/Contents/_CodeSignature/CodeResources" | wc -l` → 4, paired with `codesign --verify --deep` exit 0.
